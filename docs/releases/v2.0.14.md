# Startup Monitor 2.0.14

Исправлено пустое окно после восстановления из трея и активации уже запущенного приложения. Скрытие отложено до завершения минимизации Windows; быстрое восстановление отменяет скрытие, а Normal/Maximized устанавливается до показа содержимого WPF. Второй экземпляр больше не освобождает чужой mutex.

В компактном диспетчере процессов сохраняется ширина имён: заголовок и строки прокручиваются вместе, вертикальная виртуализация работает. Значения **Boot Impact — Low / Medium / High** обновляются сразу при переключении RU→EN→RU без перезапуска и изменения записей.

Известные COM-свойства правил брандмауэра читаются через кэшируемые динамические вызовы. Статус не загружает полные DTO всех правил. Реальный запрос статуса после изменения занял **106 мс вместо 7551 мс** в исходном замере. TTL, фильтры правил, операции безопасности и освобождение COM сохранены. Абсолютный предел CPU для любого сценария этим сравнением не заявляется.

Проверено: **1426 тестов Release, 0 ошибок, 0 пропусков**, **5 проверок развёртывания**, **8 сочетаний языка/темы/размера настоящего UI** и **8 браузерных сочетаний сайта**. Готовый установщик реально обновил рабочую копию; переносимые и установленные Service/UI запущены и проверены. Закрытие UI оставляет защиту работающей. Свежие журналы проверены без ошибок и исключений. [Подробный отчёт](https://github.com/gms-cod/SM/blob/v2.0.14/docs/AUDIT_RELEASE_v2.0.14_2026-11-04.md).

EXE и установщик подписаны самоподписанным сертификатом разработчика **Startup Monitor**. Локальный статус `Valid` не означает публичного доверия на другом компьютере и не гарантирует отсутствия предупреждения SmartScreen. GitHub Actions публикует тот же проверенный локальный установщик.
