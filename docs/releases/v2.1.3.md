# Startup Monitor 2.1.3

Release date / Дата выпуска: 2026-11-10. Branch / Ветка: `main`.

Validation / Проверка: full Release test suite **1755 passed, 0 failed, 0 skipped**. Native Windows verification confirmed temporary WFP blocking and restoration over IPv4 and IPv6, permanent COM In/Out pair readback/removal, and compensation after a controlled persistence failure. Native probes used only their own test executable; their rules were removed.

## English

This release fixes repeated firewall prompts and makes the result of a user decision consistent across the popup, access matrix and Windows Firewall rules.

- Connections from one executable are grouped into one active prompt with connection count and last observation. Reconnecting sockets and deduplication expiry no longer create identical pending prompts. An unknown process path can be recovered without retaining an unusable old prompt.
- Closing or deferring a prompt postpones its display without changing network policy. The countdown remains an explicit temporary outgoing block. The window waits for a confirmed result and distinguishes an unknown transport outcome, a rejected action and a request superseded elsewhere.
- A server lease gives a prompt to one authorized UI connection. Stopping/reconnecting the poller cancels old work and refreshes the state of an already open window.
- System-wide firewall decisions require administrative privileges. A process name alone, or a path containing StartupMonitor, no longer establishes trust.
- Permanent application policy uses the same identity in the popup and access matrix. Equivalent generated rules are consolidated without removing narrow custom exceptions. Rule changes and settings persistence are checked and compensated on failure; an incomplete rollback is reported explicitly.
- Explicitly cleared rule fields are applied. A narrow protocol/address/profile rule no longer silently stands for unrestricted application access. Deleting or disabling application policy reconciles its stored list state.
- Autonomous AI requires a valid supported decision. Missing or malformed results return to manual review. Disabling autonomy or changing its mode invalidates pending automatic work. Identical evaluations share bounded, cached work.
- The history distinguishes a deferred or superseded request from an applied network rule. An established TCP socket with no observed initiator is marked Unknown instead of being labelled outbound.
- Refreshing the AI rating in startup-entry properties updates the open window and the list together, including explanations and the manual/AI origin badge. The window follows replacement list snapshots instead of retaining an obsolete object.
- Elevated UI autostart uses a current-user interactive scheduled task. Migration keeps the previous Run entry until task registration is confirmed; unit tests use an isolated backend.
- Stopping the service cancels background AI requests and retry backoff instead of waiting for a network retry until the host shutdown timeout.

### Decision scope

Temporary rules affect outgoing connections until service restart, for at most eight hours. Permanent application decisions cover the executable in both directions, all protocols and profiles. “Allow TCP port for all applications” is an explicit system-wide exception.

Connection prompts observe periodic TCP snapshots. They do not hold the first packet until the user answers, do not provide complete UDP/QUIC detection, and do not guarantee that adding a rule overrides an external block or closes an already established connection.

## Русский

Выпуск исправляет повторяющиеся запросы фаирвола и согласует применение выбора между всплывающим окном, матрицей доступа и правилами Windows Firewall.

- Соединения одного exe объединяются в одну активную карточку со счётчиком и временем последнего наблюдения. Новые локальные порты и истечение кэша не создают одинаковые нерешённые запросы. Восстановление пути процесса не оставляет непригодную старую карточку.
- Крестик и «Отложить» откладывают показ без изменения сетевой политики. Таймер выполняет явно обозначенную временную исходящую блокировку. Окно различает подтверждение, отказ, неизвестный исход обмена и завершение запроса другим способом.
- Сервер выдаёт карточку одному авторизованному подключению. Остановка и переподключение поллера отменяют старую работу; открытая карточка получает актуальное состояние.
- Системные изменения фаирвола требуют административных прав. Одного имени процесса или подстроки StartupMonitor в пути недостаточно для доверия.
- Постоянная политика программы имеет единый идентификатор для окна и матрицы. Эквивалентные генерируемые правила объединяются с сохранением узких пользовательских исключений. Изменения правил и сохранение настроек проверяются и компенсируются при сбое; неполный откат сообщается явно.
- Очистка полей правила применяется. Узкое разрешение протокола, адреса или профиля не считается полным доступом программы. Удаление и выключение политики согласуются с сохранёнными списками.
- Автономному ИИ необходимо корректное поддерживаемое решение. Отсутствующий или некорректный результат возвращается к ручному выбору. Отключение автономности и смена режима отменяют право старого ответа менять политику. Повторные оценки объединяются, параллелизм и кэш ограничены.
- В журнале отложенные и заменённые запросы отделены от применённых правил. Установленный TCP-сокет без наблюдённого инициатора помечается Unknown, а не безусловно исходящим.
- Обновление AI-рейтинга в свойствах автозапуска синхронно обновляет открытое окно и список, включая пояснения и признак ручного/AI-рейтинга. Окно следует за заменой объектов в новых снимках.
- Автозапуск повышенного UI использует интерактивную задачу текущего пользователя. Прежний Run сохраняется до подтверждения регистрации задачи; тесты работают через изолированный адаптер.
- Остановка службы отменяет фоновые AI-запросы и сетевые повторы, не дожидаясь тайм-аута завершения хоста.

### Область выбора

Временное правило действует на исходящие соединения до перезапуска службы, максимум восемь часов. Постоянное решение относится к exe в обоих направлениях, для всех протоколов и профилей. «Разрешить TCP-порт для всех программ» — явно обозначенное общесистемное исключение.

Карточки создаются по периодическим TCP-снимкам. Они не задерживают первый пакет до ответа пользователя, не обеспечивают полное обнаружение UDP/QUIC и не гарантируют, что запись правила обойдёт внешний запрет или закроет уже установленное соединение.
