## 1. Резюме аудита потребления ресурсов (0.0% CPU Idle) и Headless-защиты

### 1.1 Почему служба сейчас потребляет CPU в фоне и как устранить нагрузку
1. **Постоянный скан сокетов в цикле `RunAsync`**:
   - В `NetworkConnectionAlertService.cs` (строка 185) условие `hasWork: () => AlertsEnabled` возвращало `true` непрерывно, поэтому `SleepAwareLoop` никогда не уходил в глубокий сон. Скан сокетов выполнялся каждые 5 секунд.
   - **Решение**: Условие `hasWork` переводится на `() => AlertsEnabled && _monitorWindowActive`. В режиме простого фона (без открытого окна мониторинга) фоновый скан полностью засыпает (`Timeout.InfiniteTimeSpan`).
2. **Паразитный опрос со стороны UI**:
   - В `MainViewModel.cs` и `NetworkSecurityHubView.xaml.cs` работали два независимых поллера (2 с и 2.5 с), которые синхронно вызывали `ScanNewConnections()` при каждом запросе.
   - **Решение**: Устранение дублирующего таймера из `NetworkSecurityHubView`. Метод `GetPendingNetworkAlerts` переводится на возврат уже имеющейся очереди без принудительного повторного сканирования ядра на каждый тикет IPC.
3. **Ликвидация тяжелых COM-вызовов `GetAllRules()`**:
   - Чтение свойств правил Windows Firewall через COM reflection занимало до 350 мс на вызов.
   - **Решение**: Внедрение в `WindowsFirewallService` потокобезопасного кэша путей правил `_firewallRulePathsCache` с TTL 60 секунд и мгновенной инвалидацией при программном создании/удалении правил через приложение.
4. **Непрерывная защита без запущенного UI (Headless Defense)**:
   - Служба автономно отслеживает подключения через легкий низкоуровневый контур.
   - Если программа в **Белом списке**: сетевой трафик безусловно разрешается, **0 алертов, 0 всплывающих окон навсегда**.
   - Если программа в **Чёрном списке**: служба автономно накладывает системное блокирующее правило Windows Firewall (Inbound + Outbound Block) и немедленно сбрасывает сетевой сокет / завершает процесс, **0 алертов, 0 всплывающих окон**.
   - Если обнаружено новое неизвестное внешнее подключение и UI закрыт: служба выполняет безопасный запуск интерфейса `StartupMonitor.UI.exe --minimized --alert` в пользовательской сессии через `UserSessionLauncher` (с учетом сессии рабочего стола Windows) либо показывает нативный системный тост.

## 2. Глубокий редизайн страницы Firewall (NetworkSecurityHubView) в стиле проекта

### 2.1 Стилистика Cyberpunk Glassmorphism
- Единая геометрия карточек с радиусом скругления `CornerRadius="8"` и мягкими контурными обводками `CardStrokeColorDefaultBrush`.
- Фирменные неоновые цветовые маркеры проекта:
  - **Emerald (#10B981)** — безопасный трафик, программы из белого списка, разрешающие системные правила.
  - **Crimson (#EF4444)** — принудительно заблокированный трафик, черный список, режим Killswitch.
  - **Amber (#F59E0B)** — сомнительные состояния сетевых сокетов, предупреждения.
  - **Neon Cyan (#00D2D3)** — живая сетевая активность, активные соединения.

### 2.2 Новая архитектура 5 изолированных вкладок:
1. **Вкладка 1: «Активные соединения» (Live Connections)**:
   - Сводные карточки метрик: Всего сокетов, ESTABLISHED, LISTENING, Заблокированные сокеты.
   - Интерактивная таблица соединений с флагами стран GeoIP и бейджами статуса.
   - Быстрые контекстные действия в каждой строке: «В белый список», «В чёрный список», «Заблокировать сокет».
2. **Вкладка 2: «Белый список» (Whitelist)**:
   - Полноценная таблица приложений, которым разрешён любой сетевой доступ без каких-либо уведомлений:
     - Колонки: Программа, Полный путь, Статус на диске, Дата добавления/изменения, Действия.
     - Панель инструментов: кнопка «Добавить программу в белый список...» (с `OpenFileDialog`), удаление выбранного приложения из списка с подтверждением, строка мгновенного поиска.
3. **Вкладка 3: «Чёрный список» (Blacklist)**:
   - Таблица принудительно заблокированных приложений:
     - При добавлении автоматически создается системное блокирующее правило Windows Firewall.
     - Кнопка «Добавить программу в чёрный список...».
     - Кнопка «Разблокировать (удалить из черного списка)» — снимает блокирующее правило в системе и удаляет запись из настроек.
4. **Вкладка 4: «Правила брандмауэра» (System Rules)**:
   - Обновленная таблица системных правил брандмауэра Windows с быстрыми фильтрами (Входящие, Исходящие, Блокирующие, StartupMonitor) и поиском.
5. **Вкладка 5: «Port Defender»**:
   - Панель защищаемых системных портов и журнал отраженных атак/банов IP с живым обратным отсчетом времени.

## 3. Расследование: куда пропали «Снимки системы» и план возврата

### 3.1 Причина проблемы
- Механизм контрольных снимков (`SnapshotsWindow.xaml`, `SnapshotManager.cs`, `SnapshotComparator.cs`) полностью работоспособен в коде, однако в основном интерфейсе:
  1. В левом боковом меню навигации (`MainWindow.xaml`) пункт «Снимки системы» вообще отсутствовал!
  2. Кнопка вызова снимков была спрятана в виде второстепенной серой кнопки в правом верхнем углу вкладки «Обзор» и дублировалась мелкой малозаметной иконкой над списком автозагрузки. При сворачивании или компактном размере окна она становилась незаметной.

### 3.2 Решение по восстановлению
1. **Добавление полноценного пункта в боковое меню навигации**:
   - В `src/StartupMonitor.UI/Views/MainWindow.xaml` добавляется элемент `NavItemSnapshots` с иконкой фотоаппарата (`IconCamera` / `Camera24`), локализованным текстом `NavSnapshots` («Снимки системы») и динамическим круглым бейджем количества сохранённых снимков.
2. **Локализация и свойства ViewModel**:
   - Добавление ключа `NavSnapshots` в `Strings.ru.resx` и `Strings.resx`.
   - Внедрение свойства `SavedSnapshotsCount` в `MainViewModel.cs` с автообновлением при создании/удалении снимков.
3. **Отображение баннера активного сравнения**:
   - Полноценная карточка сравнения «Было — Стало» с ярким визуальным акцентом и кнопкой «Сбросить сравнение».
