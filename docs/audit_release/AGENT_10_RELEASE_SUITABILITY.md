## 3. Поведение под обычным пользователем (Non-Admin) — главный раздел

**Ключевой факт: оба манифеста — `requireAdministrator`** (`UI/app.manifest:6`, `Service/app.manifest:6`).

**Что происходит при запуске UI обычным пользователем:**
- ✅ **Краша нет.** Windows сама показывает системный UAC-диалог при старте EXE — это штатный, понятный пользователю запрос, а не падение.
- ⚠️ **Отказ от UAC = программа вообще не стартует** (процесс не создаётся, до кода дело не доходит). Красивый оверлей `ShowStartupError(loc.ServiceUacCanceled)` (`MainWindow.xaml.cs:382-384`) при этом **не показывается** — он срабатывает только для *вторичных* `sc runas` из уже запущенного повышенного UI. То есть сценарий «пользователь нажал Нет в UAC» не покрыт никаким объяснением от программы.
- 🔴 **Блокер: UAC при КАЖДОМ входе в Windows.** Автозапуск UI (и ярлык `{autostartup}`, и запись HKCU Run) указывает на EXE с `requireAdministrator` → каждый логин = UAC-промпт. Для массового потребительского релиза это неприемлемо. Правильные варианты: разделить UI на непривилегированную оболочку + повышение только для операций со службой, либо автозапуск через задачу планировщика с наивысшими правами без промпта.

**`ServiceManager` без повышенных привилегий — обработан грамотно:**
- `CheckServiceStatus` читает HKLM — чтение разрешено обычному пользователю, `ServiceController.Status` тоже опрашивается. ✅
- `sc.Start()` без прав падает → ловится, повтор через `RunScElevated` (UAC `runas`) → при отказе бросается `OperationCanceledException("требуются права администратора")` → показывается понятный оверлей, не краш. ✅
- `StopService()` без прав: `ServiceController.Stop()` падает в `catch {}`, затем `proc.Kill()` чужого SYSTEM-процесса тоже молча падает → **молчаливый no-op без сообщения пользователю**. ⚠️ Оговорка.
- Фолбэк «запуск службы как обычного процесса `--console`» (`ServiceManager.cs:217-231`) без прав админа: сработает, но процесс умрёт вместе с сессией/не переживёт логофф — пользователь получит «вроде работает», а после перезагрузки — нет. ⚠️ Оговорка.
- `CleanHklmDuplicates` без прав — тихо пропускает (`catch {}`), корректно. ✅

**Защита от самоповреждения (`SystemProtectionHelper`) — сильная сторона:** стоп-листы `svchost/lsass/rpcss`, защита Winlogon/Shell/BootExecute, задач `\Microsoft\Windows\*`, системных WMI-подписок, хост-процессов (`svchost/rundll32/powershell` нельзя блочить по пути). Обычный пользователь через UI не сможет убить систему. ✅

## 5. Чеклист блокирующих проблем (must-fix до релиза)

3. 🔴 **Битая ссылка на инсталлятор в README** + отсутствие `StartupMonitorSetup-*.exe` в `installers/` — пользователю буквально нечего скачивать.

6. 🟡 Покрыть сценарий «отказ от UAC на старте» (сейчас — молчаливый незапуск) и молчаливый no-op `StopService()` без прав.
7. 🟢 Мелочи: удалить `--windows-service`-призрак, дубликат `sihost`, мусорные XML-доки `Point` в `App.xaml.cs`, поправить числа тестов (729/355/459) в README и `architecture.md`.
