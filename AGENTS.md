# Workspace Guidelines: Gemini Orchestrator & Free Subagent Swarm

Данный проект подчиняется единому регламенту роя: [SWARM_RULES.md](./SWARM_RULES.md).

## СТРОГИЙ ПРИОРИТЕТ ВЫБОРА ИСПОЛНИТЕЛЕЙ (STRICT WORKER PRIORITY)
1. **ВСЕГДА использовать OpenCode субагентов (`opencode/muse-spark-1.3-contributor-free`):**
   - Для ВСЕХ рутинных задач написания кода, генерации бойлерплейта, юнит-тестов (xUnit / pytest), параллельного аудита кодовой базы, глубокого рефакторинга, анализа логов и документации **ВСЕГДА** используются бесплатные OpenCode субагенты.
   - Запуск через CLI (`python -m engine.opencode_runner` / `opencode run`) или MCP-инструменты.
   - Модель: `opencode/muse-spark-1.3-contributor-free` (1 048 576 токенов контекста, 0$ cost).
2. **Нативные Gemini субагенты (`self` / `research`) — ТОЛЬКО В КРАЙНЕМ СЛУЧАЕ:**
   - Нативные субагенты Gemini разрешено привлекать **ТОЛЬКО В КРАЙНЕМ СЛУЧАЕ — при острой технической необходимости**:
     * Полная физическая недоступность OpenCode CLI / сетевой сбой внешнего API OpenCode;
     * Необходимость специфических внутренних браузерных инструментов Antigravity, недоступных внешним моделям.
   - Для стандартных задач кодинга, рефакторинга, написания тестов и анализа кода использование Gemini субагентов СТРОГО ЗАПРЕЩЕНО.

## Двухуровневая архитектура агентов
1. **Главный оркестратор (Antigravity Gemini):**
   - Стратегическое планирование, архитектурный дизайн, декомпозиция целей, параллельный запуск OpenCode роя.
   - Реактивный синтез результатов, архитектурные решения и финальная контрольная верификация.
   - **Запрещено:** вручную перебирать кодовую базу, читать многомегабайтные логи или находиться в циклах ожидания.
2. **Специализация роя:**
   - **OpenCode воркеры (`opencode/muse-spark-1.3-contributor-free`):** Основная рабочая сила для кодинга, тестов, рефакторинга и анализа.
   - **Gemini воркеры (`research` / `self`):** Резервный эшелон экстренного случая.

## Параллелизм и реактивная координация (No Polling / No Loops)
- Запуск воркеров выполняется параллельно за один шаг (Batch Invocation).
- Каждому воркеру ставится ортогональная, независимая задача.
- Оркестратор засыпает после постановки задач и просыпается реактивно по завершении воркеров.

## Quality Verification Checklist
По завершении задач субагентами:
- Проверить синтаксическую чистоту и компилируемость изменённого кода.
- Прогнать модульные тесты (`pytest` / `dotnet test`).
- Убедиться в отсутствии регрессий и соответствии требованиям пользователя.
