# Регламент роя агентов и оркестрации (Swarm & Orchestrator Operational Rules: AI-Core 3.5)

Данный документ регламентирует распределение обязанностей между главным оркестратором Antigravity и параллельным роем субагентов OpenCode под управлением инженерной обвязки Harness-2.

---

## 1. Архитектурная парадигма оркестра (Core Orchestration Paradigm)

- **Двухуровневая модель управления**:
  1. **Главный оркестратор (Conductor / Lean Orchestrator)** — предиктивный анализ сложности задачи, динамическое определение необходимого числа субагентов, одновременный запуск роя, реактивный приём ответов, синтез консенсуса, архитектурные решения и финальная контрольная верификация.
  2. **Оркестр субагентов (Agent Orchestra)** — параллельные специализированные воркеры для решения конкретных поисковых, исследовательских, тестовых и инженерных задач.
- **Главный постулат**:
  Оркестратор **НИКОГДА** не выполняет тяжелую механическую, поисковую или исследовательскую рутину своими руками. Вся рутина безусловно делегируется субагентам роя.
- **Информированность дирижёра**:
  Оркестратор в реальном времени знает, чем занят каждый музыкант оркестра, на какой фазе находится выполнение и каков примерный процент готовности задачи каждого агента.

---

## 2. Максимальный размер оркестра и матрица триажа (Sizing & Triage Matrix)

### Максимальный лимит субагентов в оркестре:
- **Установленный предел: до 8 параллельных субагентов** (научно и технически обоснованный оптимум).
- Этот предел предотвращает сетевой троттлинг и исчерпание лимитов Zen API (6–8 потоков), обеспечивает бережное использование RAM (~1–1.5 ГБ на весь рой) и даёт ускорение кодинга и рефакторинга до 8 раз.

### Предиктивная матрица сложности (Task Complexity & Swarm Sizing):
Оркестратор прогнозирует сложность задачи перед запуском и выбирает необходимое число субагентов:

| Уровень сложности | Описание задачи | Прогноз времени | Размер роя | Назначенный профиль / стратегия |
| :---: | :--- | :---: | :---: | :--- |
| **Уровень 1** | Точечные микро-правки, опечатки, 1–2 строки, флаги конфига | 5–10 сек | **0 субагентов** | `DIRECT_ORCHESTRATOR` (оркестратор делает сам за 2-3 сек) |
| **Уровень 2** | Локальная функция, модульный тест, DTO, вспомогательный парсер | 15–30 сек | **1 субагент** | `SOLO-FAST` под Harness (`opencode/beam-free` или `deepseek-v4.1-flash-free`) |
| **Уровень 3** | Архитектурный консилиум, сложная логика, многопоточность, P/Invoke, гонки | 1–3 мин | **3–4 субагента** | `TRIAD-REVIEW` / `QUAD-AUDIT` (DeepSeek + Nemotron + Beam + Flint) |
| **Уровень 4** | Масштабный рефакторинг репозитория, шардинг файлов, сквозной аудит безопасности | 3–8 мин | **до 8 субагентов** | `FULL-ORCHESTRA` / `MASS-SHARDING` (8 параллельных воркеров) |

## 3. Обязательный 3-минутный отчет с процентом готовности (`schedule`)

### Жесткое требование операционного цикла:
При запуске любых фоновых субагентов оркестратор **СТРОГО ОБЯЗАН** немедленно взвести таймер:
`schedule(DurationSeconds=180, Prompt="Регулярный 3-минутный опрос статуса...", TimerCondition="any")`.

### Расчет примерного процента готовности задачи:
Процент рассчитывается динамически по фазам жизненного цикла субагента:
- **0% – 15% (Инициализация)**: Подготовка песочницы, копирование токенов, загрузка ДНК проекта.
- **15% – 45% (Исследование и чтение)**: Обход целевых файлов, AST-анализ, выявление зависимостей.
- **45% – 85% (Генерация решения)**: Формирование ответа/кода (пропорционально объему вывода символов в `char_count`).
- **85% – 95% (Верификация)**: Самопроверка инвариантов, форматирование отчета.
- **100% (Финиш)**: Статус `DONE`, итоговый Markdown-отчет сгенерирован.

### Каноничный формат отчета пользователю каждые 3 минуты:
```markdown
### ⏱ Отчет состояния оркестра [T+03:00] (Прогноз до финиша: ~2 мин)

| Субагент | Модель | Текущая подзадача | Прогресс готовности | Затрачено | Текущий статус / последняя строка |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **CONCURRENCY_AUDITOR** | `deepseek-v4.1-flash-free` | Аудит гонок в NativeProcessTraceSession | **~65%** | 180с | 🟢 Анализ графа блокировок |
| **RESOURCE_CLEANER** | `nemotron-3.5-lightning-free` | Проверка SafeHandle и IDisposable | **~72%** | 180с | 🟢 Проверка цепочки освобождения |
| **TEST_GENERATOR** | `beam-free` | Генерация негативных xUnit тестов | **~50%** | 180с | 🟢 Формирование тест-кейсов |
```
Если работа субагентов продолжается, оркестратор немедленно перезапускает 3-минутный таймер до полного завершения.

## 4. Архитектурная обвязка Harness-2 (Project DNA & Persistent Lessons)

Любой вызов субагента или генерация кода оркестратором обязаны происходить под контролем Harness:
1. **Project DNA (ДНК проекта)**: Автоматическое выявление стека кодовой базы (C#, .NET 8, Win32 P/Invoke, ETW, WPF, Python) и специфических правил безопасности (освобождение дескрипторов в `finally`, отсутствие sync-over-async, корректный маршалинг строк).
2. **Persistent Lessons (Память граблей)**: Долговременный банк уроков исключает повторение известных сбоев (переполнение аргументов Windows 8191 символ, артефакты кодировки UTF-8 BOM в PowerShell 5.1, блокировки SQLite).
3. **Zero-Crash & Zero-Stub**: Категорический запрет плейсхолдеров `// TODO`, `# TODO`, `pass`, исключений-заглушек `NotImplementedException`, пустых `catch { }`. Обязательные подробные русские XML-комментарии для всего создаваемого/изменяемого кода.
4. **Execution Harness (Контур обязательной проверки)**: Сгенерированный код считается принятым ТОЛЬКО после реальной проверки компилятором (`dotnet build`) и 100% успешного прохождения модульных тестов (`dotnet test`).

## 5. Доступные модели OpenCode и категорический запрет OpenRouter (0$ Cost)

### Белый список проверенных моделей (0$ Cost, верифицировано живыми тестами):
1. **`opencode/deepseek-v4.1-flash-free`** (~13с) — Флагман сложной логики, C#, Win32, выявление багов, инварианты контрактов.
2. **`opencode/beam-free`** (~12с) — Абсолютный лидер скорости, генератор тестов xUnit/NSubstitute, скриптов и соло-задач.
3. **`opencode/nemotron-3.5-lightning-free`** (~14с) — NVIDIA 262K, системный анализ многопоточности, дедлоков и дескрипторов.
4. **`opencode/nemotron-3.5-super-vl-free`** (~14.5с) — Сверхдлинный контекст 1M токенов, мульти-файловый аудит.
5. **`opencode/glm-5.3-flash-free`** (~16.4с) — Сверхдлинный контекст 1M токенов, архитектурный аудит всей кодовой базы.
6. **`opencode/flint-40b-free`** (~18.8с) — Плотная 40B модель общего назначения для параллельного шардинга.

### Черный список (КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНЫ):
- **ВСЕ МОДЕЛИ OPENROUTER (`openrouter/*`)** — ПОЛНОСТЬЮ УДАЛЕНЫ И ЗАПРЕЩЕНЫ ПО УКАЗАНИЮ ПОЛЬЗОВАТЕЛЯ.
- `muse-spark`, `space-bunny`, `longcat-2.5-preview-free` (UnknownError шлюза Zen API).
- `crouton-alpha-free`, `pulse-alpha-free` (UnknownError сервера).
- `mimo-v2.6-flash-free` (таймауты >20с / перегрузка провайдера).
- Платные или недоступные модели (`minimax`, `gemma-4-31b`, `llama-3.3-70b`).

## 6. Детальные процедуры и примеры запуска

### Процедура 1: Запуск консилиума через CLI роя
Для архитектурного анализа, поиска багов и аудита безопасности:
```powershell
python D:/Nas_sync/Projects/Swarm_agents/scripts/run_swarm.py `
    --profile TRIAD-REVIEW `
    --workdir <путь_к_проекту> `
    --task "Аудит потокобезопасности и отсутствия утечек дескрипторов"
```
*Для максимального оркестра из 6–8 субагентов*:
```powershell
python D:/Nas_sync/Projects/Swarm_agents/scripts/run_swarm.py `
    --profile FULL-ORCHESTRA `
    --workdir <путь_к_проекту> `
    --task "Масштабный рефакторинг пула подсистем и сквозной аудит"
```

### Процедура 2: Делегирование задач через инструмент MCP
Для точечного кодинга, генерации модульных тестов и рефакторинга:
```python
# Вызов через call_mcp_tool:
call_mcp_tool(
    ServerName="opencode-subagent",
    ToolName="delegate_task_to_subagent",
    Arguments={
        "instruction": "Напиши модульные тесты xUnit для класса NativeProcessTraceSession с проверкой отмены через CancellationToken",
        "model": "opencode/deepseek-v4.1-flash-free",
        "reasoning_effort": "medium"
    }
)
```

### Процедура 3: Прямой запуск CLI OpenCode
В изолированной песочнице с быстрым неблокирующим вводом:
```powershell
& opencode run --pure -m opencode/deepseek-v4.1-flash-free --auto "Напиши функцию безопасного чтения FileTime на C#"
```

### Процедура 4: Автоматический Fallback на нативных субагентов
Если ни одна внешняя бесплатная модель OpenCode временно недоступна, оркестратор обязан бесшовно вызвать нативного субагента:
```python
invoke_subagent(
    TypeName="self",
    Role="Concurrency Architect",
    Prompt="Проведи аудит потокобезопасности модуля согласно чеклисту Harness-2..."
)
```
Завершать работу ошибкой категорически запрещено — нативные субагенты гарантируют 100% надежность финиша задачи.
